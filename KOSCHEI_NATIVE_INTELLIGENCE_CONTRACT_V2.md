# Koschei Native Intelligence Contract v2

Status: active architectural contract

Supersedes: `KOSCHEI_NATIVE_INTELLIGENCE_CONTRACT_V1.md`

## 1. Scope decision

Koschei Lang is an independent programming language, compiler, runtime and security universe.

Koschei Sentinel is frozen as a separate project. The previously proposed Sentinel-to-Lang merge is cancelled.

Koschei Lang MUST NOT depend on Sentinel code, Sentinel model artifacts, Sentinel datasets, Sentinel runtime state, Sentinel credentials or Sentinel availability in order to compile, execute, verify, recover or preserve Khar.

If Sentinel is ever resumed, it may communicate with Koschei Lang only through an explicitly versioned external interface. Such an interface is optional and replaceable. Sentinel is never a Lang subsystem, sovereign runtime root, seventh stone, master key, hidden authority source or required model provider.

## 2. Lang-native intelligence

Koschei Lang may research and operate its own optional native-intelligence components. This work belongs to Lang itself and is not a continuation, rename or migration of Sentinel.

The current research base model is:

`Qwen/Qwen3.5-397B-A17B`

The model is replaceable. Khar, compiler truth, Sathra, Aevra/Veyra identity, Matrix/Hara reality, Morth/Vormir finality and Nur/Nyr visibility laws MUST remain valid when no model is present.

The model may observe, classify, reason, explain, rank bounded futures and propose actions. It carries zero execution authority.

## 3. Authority boundary

There is no `model_execute()` side door.

A model output is evidence only. It cannot:

- mint authority;
- substitute for a missing Khar axis;
- weaken six-of-six Sathra concurrence;
- rewrite Khar;
- resurrect Morth;
- replace current Hara;
- create Aevra birth by copying bytes;
- turn an observer projection into living reality;
- convert knowledge into power.

Any model-originated proposal must pass the same constitutional execution gates as any other proposal.

## 4. Canonical model identity

A Lang-native model identity must bind at least:

- canonical Khar identity;
- exact base-model registry ID;
- immutable base-model revision;
- verified base-weight identity;
- exact Lang curriculum digest;
- exact training corpus/export identity;
- exact training configuration digest;
- adapter/checkpoint digest;
- execution/run receipt identity;
- exact Koschei Lang source commit;
- `authority = false`.

Mutable model names, mutable `main`, a Drive folder, a single adapter or a model account are not sufficient identity.

## 5. Curriculum boundary

The active curriculum remains Lang-native from N0 onward:

### N0 — Native language birth
Parser, typed semantics, native sigils and sealed MIR.

### N1 — Galaxy identity
Aevra/Veyra identity, copy-is-not-birth and cross-Veyra non-transfer.

### N2 — Khar and six-axis reality
Exact six-axis same-event concurrence, no partial authority, witness separation and one-shot Sathra.

### N3 — Matrix, Morth and Vormir
Current Matrix/Hara, irreversible death, Event Horizon, durable epoch sacrifice and rebirth as new identity.

### N4 — Adversarial learning resistance
Nur/Nyr, rotating observer surfaces, bounded reconnaissance feedback, cross-session/cross-Veyra non-transfer and No Golden Tray.

### N5 — Survival intelligence
Khar-preserving branch eligibility, hard ceilings, deterministic least-loss selection and authority-free bounded autonomy.

### N6 — Lang defensive reasoning
Evidence-grounded defensive reasoning over Koschei Lang's own adversarial suites. Admission requires current Lang-native evidence and anti-shrink gates. It is not a Sentinel migration stage and does not import Sentinel artifacts by inheritance.

Sector-specific training may be added later as explicit optional curricula. It must not redefine the language core.

## 6. Sentinel boundary

Active Lang training and release paths MUST reject a curriculum that claims any of the following:

- Sentinel is merged into Lang;
- Sentinel intelligence is folded into Lang;
- Sentinel historical artifacts are an inherited training source;
- Sentinel availability is required for Lang operation;
- a Sentinel model identity can become a Lang model identity by relabelling.

Historical Git commits may preserve superseded experiments for auditability. They are not active architectural authority.

## 7. Training method

Initial model specialization should use a pinned and reproducible LoRA/PEFT-style supervised fine-tuning path. Post-training methods may be researched only after the supervised baseline and its evaluators are stable.

A completed adapter is not automatically promoted or deployed.

The constitutional holdout remains evaluation-only and MUST NOT be included in optimizer training data.

Train, validation and held-out test roles remain separated. The trainer must not receive test data as optimizer input.

## 8. Storage and execution

Git stores source, contracts, manifests and verification logic, not full base weights, secrets or private corpora.

Google Drive may act as a Koschei Lang training vault for corpus releases, validation receipts, preflight evidence, run receipts, adapters/checkpoints and evaluation results.

Remote training mirrors must be content-bound to sealed local exports. Training mirrors should expose only the data required for training/validation; held-out test material remains outside the trainer trust domain.

## 9. CI independence

Hosted GitHub Actions are not a required trust root for Koschei Lang.

Canonical release validation may run locally or in Colab and emit a sealed validation receipt bound to the exact source commit and environment evidence. A hosted CI status bit cannot substitute for that receipt.

## 10. Anti-drift laws

1. Koschei Lang remains independently operable without Sentinel.
2. Sentinel remains outside Lang unless a future explicit architectural decision creates a versioned external interface.
3. Model confidence never substitutes for compiler truth, Khar, Sathra or evidence.
4. No model output is authority.
5. No model is a seventh stone or Golden Object.
6. No training artifact inherits trust merely because it existed in another Koschei project.
7. Customer Veyra topology must not become transferable training truth.
8. A better model may improve reasoning quality; it cannot weaken execution laws.
9. Claims of hardware isolation, PQ resistance or inference resistance require separate evidence.
10. Active Lang contracts and training releases must contain no Sentinel-merge assumption.
