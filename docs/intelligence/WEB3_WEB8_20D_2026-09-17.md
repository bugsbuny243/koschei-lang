## 2026-09-19 fresh intake

### RFC 10032 reinforces algorithm/status separation
RFC 10032, announced 2026-09-19, documents the AEGIS authenticated-encryption family. It is an IRTF/CFRG Informational RFC and explicitly not an Internet Standard.

**Lang opportunity:** crypto-provider metadata should distinguish algorithm identity from standardization stream/status, implementation/provider availability and application policy.

**Threat:** baking a newly numbered RFC directly into language semantics would confuse publication status with universal suitability/deployment.

**Design review candidate:** provider traits/metadata can expose algorithm family, security properties, provider implementation, protocol compatibility and policy status without requiring new syntax.

### AIN-WRP reinforces typed separation of identity evidence and authority
`draft-tanase-ain-authoritative-resolution-00`, published 2026-09-18, separates persistent agent identity, credentials/proof-of-control, delegated authority, operational eligibility, policy decision and execution.

**Lang opportunity:** this supports the existing architecture direction of protocol-neutral `Evidence<T>`, verified principal and scoped authority boundaries.

**Threat:** hard-coding an Internet-Draft's identifiers or wire format into language semantics would create premature coupling.

**Design review candidate:** library/runtime contracts should be able to require fresh relationship evidence and scoped authority before sensitive effects, while leaving the concrete registry/identity protocol replaceable.

### Draft expiry is a useful design filter
ADL, SPICE Intent/Inference Chain, RVP and UPIP revisions reach expiry on 2026-09-19 unless updated/replaced. Their architectural ideas can remain useful, but draft names/wire formats should not become normative Lang dependencies without stronger standardization/deployment evidence.

## Standards reality
No accepted Web4/Web5/Web6/Web7/Web8 generation standard was identified. RFC 10032 is real but Informational/IRTF; AIN-WRP is an Internet-Draft. Do not encode Web-generation branding or transient draft wire formats into language semantics.
