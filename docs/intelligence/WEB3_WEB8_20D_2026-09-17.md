# Web3–Web8 Intelligence — Koschei Lang

Window: 2026-08-29 → 2026-09-23

Only architecture-level signals are applied. Daily news does not automatically become a language feature.

## Existing directions
Crypto-provider agility; identity/capability/delegated-scope/effect authorization separation; commit-time authority/state freshness; untrusted observation vs verified state; evidence/receipt hooks; artifact-identity continuity.

## 2026-09-23 fresh intake

### Effect ordering is a first-class security concern
September 23 reporting on CVE-2026-90898 in the Bifrost AI gateway describes a management path where an stdio MCP client command could be started before the normal MCP handshake when management authentication was disabled.

**Lang opportunity:** strengthen the architecture principle that security-sensitive effects must occur only after required identity, authority, policy and artifact checks have succeeded.

**Threat:** APIs can expose correct verification primitives but still be unsafe if side effects occur before those primitives are enforced.

**Design review:** effect-boundary contracts/preconditions and an auditable distinction between `prepare/resolve/verify` and `commit/effect`; no Bifrost- or MCP-specific syntax.

### Open verification reinforces evidence semantics, not a new language feature
LF Decentralized Trust and Advanced AI Society launched Proof-of-Control work on 2026-09-23 around tamper-evident evidence generated as agents act.

**Lang opportunity:** evidence values should preserve what was measured/proven, source/mechanism identity, freshness and relation to an effect.

**Threat:** a generic `verified=true` abstraction can collapse different claims—identity, policy compliance, execution and resulting state—into one unsafe boolean.

**Design review:** typed/structured evidence claims whose semantics remain explicit across runtime/tool boundaries.

### Client-side validated Web3 state reinforces trust-state typing
RGB Protocol v0.11.1 dropped the RC tag on 2026-09-23. RGB's client-side validation model is another concrete example where relevant application state/evidence is not reducible to a simple base-chain read.

**Lang opportunity:** keep external state origin and validation mechanism explicit; avoid assuming “on-chain” is the only canonical trust source.

## Standards reality
No accepted IETF/W3C Web4/Web5/Web6/Web7/Web8 generation standard was identified in the last 24 hours. Proof-of-Control is open-community/LFDT work; RGB is a production protocol; MCP is an open application protocol. Do not encode Web-generation branding or transient vendor wire formats into language semantics.
