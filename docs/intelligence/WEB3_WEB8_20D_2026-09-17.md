# Web3–Web8 20-Day Intelligence — Koschei Lang

Window: 2026-08-29 → 2026-09-17

Only architecture-level signals are applied. Daily news does not automatically become a language feature.

## What matters to Lang

### 1. Crypto agility
Ethereum’s post-quantum roadmap reinforces avoiding hard-wired signature assumptions. Account-level signature agility and later consensus-layer migration show why cryptographic choices should be replaceable under explicit policy where practical.

**Architecture direction:** keep signature/KEM/hash/commitment/proof backends behind explicit capability/policy boundaries. Do not bind language semantics to one cryptographic family.

### 2. Authority is separate from identity and computation
September agent-delegation and execution-finality drafts converge on a useful security invariant: possession of an identity/credential or successful computation does not automatically authorize a concrete effect.

**Architecture direction:** preserve distinct concepts for identity, capability, delegated scope, action intent and effect authorization. Capability attenuation should be monotonic across delegation where supported.

### 3. Untrusted observation vs verified state
Recent cross-chain failures show that cryptographically valid downstream actions can originate from incorrect or insufficiently validated observations.

**Architecture direction:** make it possible for APIs/runtime contracts to distinguish `untrusted/external observation` from `verified/canonical state` before security-sensitive effects. Exact syntax remains a design task; this intelligence note does not mandate a new type keyword.

### 4. Evidence and receipts
Agent-protocol drafts increasingly include receipts/provenance. Security-sensitive effects benefit from binding who authorized the action, the policy/capability used and the resulting state.

**Architecture direction:** evaluate a first-class audit/evidence interface at runtime boundaries without forcing every application into a single storage format.

## Design review queue
- Crypto-provider abstraction and migration policy.
- Capability attenuation semantics.
- Effect authorization separate from authentication.
- Trusted-state boundary / verification interface.
- Evidence/receipt hooks for security-sensitive execution.

## Non-goals
- Do not implement Web4/Web5/Web6/Web7/Web8 branding as language features.
- Do not adopt an Internet-Draft as a normative dependency merely because it is new.
- Do not add syntax until benchmark/design review shows a language-level benefit over library/runtime implementation.
