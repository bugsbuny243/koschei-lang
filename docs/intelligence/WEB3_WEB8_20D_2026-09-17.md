## 2026-09-20 fresh intake

### AIMS working-group adoption strengthens identity/authority separation
IETF WIMSE adopted AIMS as `draft-ietf-wimse-aims-00`. The architecture separates stable agent identity, short-lived runtime credentials, authentication, delegated context, authorization, observability and remediation.

**Lang implication:** preserve provider-independent identity and authority semantics. Stable identity MUST NOT imply long-lived credentials, and credential validity MUST NOT imply execution authority.

### HAPS reinforces exact-action human approval without making approval a permit
The experimental Human Approval and Presence Specification (HAPS) binds portable approval evidence to the exact consequential action, relying party, freshness window and replay-resistant challenge.

**Lang implication:** approval evidence is an input to a fresh runtime authorization decision. `APPROVAL != EXECUTION`; approval for action A MUST NOT authorize action B.

### Agent-accountability drafts reinforce causal evidence without justifying new syntax
IETF Datatracker shows the HJS accountability draft (`draft-wang-hjs-accountability-01`) expiring 2026-09-20. HJS/JEP/AAP explore responsibility receipts, judgment-event provenance, delegation/termination and task-to-task causal references. They remain Internet-Draft proposal work, not adopted standards.

**Opportunity:** strengthen the existing runtime/library evidence model so security-sensitive effects can optionally carry causal references linking principal/delegation, initiating judgment/task, downstream task and resulting effect/receipt.

**Threat:** hard-coding transient HJS/JEP/AAP identifiers or wire formats into language semantics would couple Lang to drafts that may expire, be replaced or never standardize. A signed receipt must also not become an implicit authority token.

**Competitor gap:** a security-first language/runtime can make provenance/evidence composable while keeping authority, state validity and execution permission as distinct concepts.

**Design review candidate:** evaluate protocol-neutral `Evidence<T>` / `Cause<T>` / scoped-authority library contracts and runtime hooks. Require evidence verification and then a fresh, independently derived native authorization decision before any execution permit may be minted. Evidence is policy input and MUST NOT itself authorize an effect; do not add syntax until benchmarks show a language-level advantage.

### Draft lifecycle remains a design filter
The 19–20 September expiry boundary for multiple agent drafts reinforces the existing rule: architectural ideas may be retained, but draft names/wire formats do not become normative Lang dependencies without stronger standardization and deployment evidence.

## 2026-09-21 fresh intake

### Intent, subject identity, resolution and effect should remain separable
`draft-li-rttp-intent-addressing-01`, published 2026-09-20, proposes an `rttp` URI that identifies an intent claim toward a subject while deriving an address computationally and warning against navigation/launcher confusion. It is an Independent Submission Informational Internet-Draft, not an RFC.

**Lang opportunity:** this reinforces a protocol-neutral architecture where `Intent<T>`, subject identity/evidence, resolution evidence and an effect capability are not interchangeable values.

**Threat:** collapsing identifiers, locators and executable capabilities into one string-like primitive can allow confused-deputy/handler mistakes.

**Design review candidate:** evaluate library/runtime contracts that distinguish declarative intent from resolved target and authorized effect. Do not add RTTP-specific syntax.

### AIIP/AIID reinforces revocation-aware effect boundaries
`draft-sogomonian-aiip-aiid-00`, published 2026-09-20, combines durable identity, an agent access plane, execution receipts, freeze and revocation controls. It is Experimental Internet-Draft work.

**Lang opportunity:** security-sensitive effects should be able to require fresh authority/revocation state at the effect boundary and emit evidence/receipts without binding semantics to a single agent protocol.

**Threat:** treating a signed receipt or protocol identity as an effect capability would recreate identity-vs-authority confusion.

**Design review candidate:** retain separate abstractions for `IdentityEvidence`, scoped `Authority`, freshness/revocation witness, `Intent`, and effect receipt; exact syntax/API remains open.

### Standards lifecycle filter
AGTP revision 01 reaches its stated 2026-09-21 expiry. Architectural ideas may be useful while transient draft names/wire formats should not become normative language dependencies.

## Standards reality
No accepted Web4/Web5/Web6/Web7/Web8 generation standard was identified. AIMS is on the IETF WIMSE Working Group track; HJS/JEP/AAP remain Internet-Draft proposal families; HAPS is an experimental open specification. Do not encode Web-generation branding or transient proposal formats into language semantics.
