# Ownership Model v1

This document defines Koschei's ownership rule precisely, says what it
guarantees, and lists the evidence behind it. It closes 1.0 gate 4
("formalized ownership/region model where needed for native safety").
`docs/AFFINE_RESOURCES_V1.md` is the user guide. This document is the
specification the checker is tested against.

## Why this is the ownership model Koschei needs

Native safety splits into two parts.

- **Memory safety.** Koschei has no pointers, no pointer arithmetic, no
  manual allocation and no foreign-function interface. The native backend
  emits Go. User code is translated without Go's `unsafe` package, so
  memory safety comes from Go's garbage collector and bounds checks. The
  broker runtime uses `unsafe` once, to install the seccomp filter. That
  code is generated by the compiler and is part of the trusted base
  (`docs/THREAT_MODEL_V1.md`). Koschei does not need Rust-style lifetimes
  or regions for memory safety.
- **Authority safety.** This is what Koschei promises beyond Go. A
  capability token must not be duplicated, so authority can be handed on
  but never copied. This document is about that rule.

The same checked program feeds `ks run` and `ks build`. The rule is
enforced at compile time, before either executor runs, so the native
binary inherits it. Gate 2 (executor equivalence) covers the rest.

## Definitions

- A type is **affine** when it is a capability type (`DiskCaps`,
  `DiskReadCaps`, `NetCaps`, `EnvCaps`, `PersistCaps`, `ServeCaps`, …), or a
  struct with an affine field, directly or through nested structs.
  `SystemCaps` is affine. Plain values (`Int`, `String`, `List<Int>`, …) are
  not.
- A **binding** is a `let`, a parameter, a `for` variable or a `match` arm
  binding.
- A binding of affine type is an **owner**. Each owner is *live* or
  *moved*.

## The rule

> **On no execution path is an owner used after it was moved.**

A use is either a **borrow** or a **move**.

| Expression | Effect on owner `x` |
|---|---|
| `x.method(…)`, `x.field` read, `x` inside a non-affine operator | borrow |
| `let y = x` | move |
| `f(x)` where the parameter is affine | move |
| `return x` | move |
| `S { f: x }`, `[x]`, `{k: x}` | move (lists and maps of tokens are refused anyway, KS2401) |
| `consume(h.t)`, an affine field taken by value | moves the whole owner `h` (no partial moves in v1) |
| `caps.disk`, `caps.net`, … | derives a root; does not move `caps` |

Borrowing a moved owner is also a use after move (`KS3931`).

## How the checker decides it (the conservative approximation)

The checker (`koschei/affine_resources_v1.py`) tracks a set `M` of owners
that *may* have been moved, walking the program once.

1. **Sequence.** Statements update `M` in order. A use of an owner in
   `M` is `KS3931`.
2. **Branches** (`if`/`else if`/`else`, `match` arms). Each branch starts
   from the same `M`. After the join, `M` is the union of what the branches
   moved. If a branch *may* move `x`, `x` is unavailable after the join.
3. **Loops** (`while`, `for`). Moving an owner declared outside the loop
   is `KS3932`. Iteration counts are not tracked. A `while` condition runs
   before every iteration, so it is checked as part of the loop. Owners
   declared inside the loop body are fresh on each iteration.
4. **Scopes.** Owners declared in a block are forgotten when it ends.
5. **Mutability.** `let mut` on an affine binding is `KS3930`, so an owner
   cannot be re-filled after a move.

Every approximation errs towards refusing. The checker ignores `return`,
`break` and `continue` when joining, and it never counts loop iterations.
So some safe programs are refused, for example a move followed by an
immediate `return` inside a loop. No unsafe program should be accepted.

## Soundness, and how it is checked

**Claim (soundness).** If `ks check` accepts a program, then on every
execution path no owner is used after it was moved.

The claim is checked against an independent reference. `tools/fuzz/affine_fuzz.py`
generates programs that move, rebind, wrap and borrow tokens. These moves sit
inside nested `if`/`else if`/`while`/`for`, inside loop and branch conditions,
and around `break`, `continue` and `return`. A separate **oracle** runs each
program along *every* path:
- Unknown booleans take both values.
- Loop counters are exact.
- `&&` short-circuits.
- Control flow is followed precisely.

The oracle implements the rule above directly. It shares no code with the
checker.

- **Unsound** (the checker accepts, the oracle finds a path that uses a
  moved owner) is a finding and fails the run.
- **Conservative** (the checker refuses, the oracle finds no violation)
  is counted. It is expected, and it is about 4% of programs.

The fuzzer runs on every pull request (`tests/test_fuzz_smoke_v1.py`) and
in larger nightly batches (`.github/workflows/fuzz.yml`).

### What it found

The first run found a soundness bug. The checker evaluated a `while`
condition once, as if it ran once. A program like this was accepted:

```ks
while n < 2 && takes(tok) {
    n = n + 1
}
```

It handed the same token to `takes` on every iteration, which duplicates
authority. The condition is now checked inside the loop rule (rule 3), and
it gets `KS3932`. `tests/test_affine_resources_v1.py` keeps a regression
test. With the fix reverted, the fuzzer reports the bug again within
1,500 programs on every seed tried. With the fix, 12,000 programs across 6 seeds give no
finding.

## Limits

- **Tested, not proved.** Soundness is checked against an oracle on
  generated programs. It is not a machine-checked proof about the Python
  checker. A future step is a mechanised proof over a core calculus.
- **The generated fragment.** The fuzzer covers tokens, rebinding,
  struct wrapping and field extraction, consuming calls, borrowing calls,
  `if`/`else if`/`else`, `while`, `for`, `break`, `continue` and `return`.
  `match` arms, closures (capturing a token is refused, KS1103), helper
  chains (covered by `capability_fuzz.py`) and modules are not generated
  by this fuzzer.
- **Affine, not linear.** Tokens may be dropped unused. Exactly-once
  resources are handled by typestate (`docs/TYPESTATE_RESOURCES_V1.md`),
  not by this rule.
- **No partial moves or borrows.** Moving one affine field moves the whole
  struct. This is conservative by design.
- **Trusted base.** Go's memory safety, the compiler's own runtime code
  (including the broker) and the type checker that classifies types as
  affine are trusted, not checked here.
